Chat App Writeup

What / Where / Who

Action 1: Creating a Chat

What: Creating a new chat room with a custom title and channel.

{
  activity: "Create",
  type: "Chat",
  title: "Chat Title",
  channel: crypto.randomUUID(),
  published: Date.now()
}

Where: Chats are stored in a shared directory channel:

group-project-chat

All users of the app can discover any available chats.

Who: Public (everyone with app access)

Action 2: Join Chat

What: Recording that a user has either joined or opened a chat.

{
  activity: "Join",
  type: "Chat",
  target: "chat-channel-id",
  published: Date.now()
}

Where: This is stored in a channel unique to each user:

[actor-id]/chat-app

This allows the app to keep track of which chats a user has joined.

Who: Only the user that is currently logged in

allowed: []

Action 3: Send Message

What: Sending a message inside a chat room.

{
  type: "Message",
  content: "Hello world",
  published: Date.now()
}

Where: This is stored in a unique channel specific to the chat room. This channel is created when the chat is created and it keeps messages separated by chat.

Who: Public to anyone who is viewing that chat (no allowed list)

Action 4: Broadcast

What: A pinned announcement message that is shared and editable by all users.

{
  type: "Broadcast",
  content: "Important announcement",
  updated: Date.now()
}

Where: This is stored in the chat’s channel.

Who: All users in the chat.

Note: This feature hasn't been implemented yet, but there is a placeholder in the UI of the planned design.

Other Design Decisions

  • Separate channels for directory and chat: I used one shared directory channel to store chat creation objects but separate channels for the message sof each chat in order to keep the system organized.
  • The join action is stored privately using an empty allowed list. This allows the app to remember which chats a user has joined without exposing that information to others.
  • I allowed polling in Graffiti discovery so that message updates happen in real time and makes the chat feel more responsive and interactive.
  • I allowed users to delete their own messages to recover from mistakes.
  • I used feedback such as “Sending…” or “Deleting…” to indicate when something is in progress.
